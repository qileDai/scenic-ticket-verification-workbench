# 景区门票团购核销异常分诊交互复核工作台

## 项目简介

本项目是一个纯前端业务工具，专门为景区票务运营、团购平台对接和客服专员设计。围绕**团购券码、核销记录、入园闸机、异常原因、补录申请、游客凭证**等核心对象，提供完整的异常分诊、凭证复核、补录管理和对账分析功能。

## 技术栈

- **前端框架**: SolidJS 1.8+
- **开发语言**: TypeScript 5.3+
- **构建工具**: Vite 5.0+
- **状态管理**: solid-js/store
- **表单校验**: Zod 3.22+
- **图表展示**: lightweight-charts 4.1+
- **路由管理**: @solidjs/router
- **数据存储**: localStorage（支持未来迁移至 IndexedDB/REST API）

## 业务规则

### 规则1：异常处理建议计算
根据券码状态、闸机记录、游客凭证和对账批次自动计算异常处理建议：
- 数据完整且一致 → 正常处理
- 缺少关键字段 → 建议保存草稿，补充信息
- 券码过期 → 需要特殊审批或补录申请
- 闸机离线但在线核销 → 数据异常需人工复核

### 规则2：重复核销强制入队
当出现券码重复核销时：
- ✅ 必须进入异常队列
- 📝 记录触发字段、阈值、实际值
- 👤 指定处理人和处理时限
- ⚠️ 高优先级告警通知

### 规则3：一致性校验前置
分诊核销异常前必须验证：
- 团购券码 ↔ 核销记录 ↔ 入园闸机 ↔ 游客凭证
- 缺少关键字段时只允许保存草稿
- 不允许跳过校验直接确认

### 规则4：指标聚合分析
支持多维度聚合查询：
- **按日**：每日核销成功率趋势
- **按批次**：各批次异常率对比
- **按责任角色**：个人工作量统计
- 所有指标支持明细溯源

### 规则5：状态流转限制
```
草稿 → 待复核 → 待补充 → 已确认 → 已归档
                    ↘ 已驳回 → 草稿
```
- 驳回必须填写原因（否则无法提交）
- 已归档不可逆
- 每个状态有明确的下一步选项

## 常见问题

### Q: 为什么页面显示空白？
A: 请确保已运行 `npm install` 安装依赖，然后执行 `npm run dev` 启动开发服务器。

### Q: 如何重新初始化 Seed 数据？
A: 清除浏览器 localStorage 后刷新页面，或在应用中使用「重置数据」功能。

### Q: 支持哪些浏览器？
A: 支持现代浏览器（Chrome、Firefox、Safari、Edge 最新版本），需要支持 ES2020+ 特性。

### Q: 数据存储在哪里？
A: 默认使用浏览器的 localStorage，数据保存在本地，无需后端服务器。

### Q: 如何扩展到真实后端？
A: 替换 `services/storage.ts` 中的 `MockApiService` 实现，改为调用 REST API 即可。
